# AI 日程任务操作、睡眠时段与 Markdown 对话设计

## 目标

让 AI 学习教练能把用户明确提出的日程和任务增删改请求转换为可审阅、可一键应用的本地变更；睡眠打卡改为入睡与起床时间并自动计算时长；AI 对话以安全、可读的 Markdown 气泡显示。

## 范围与安全边界

- AI 可提议新增、修改或删除日程和任务。
- 每一批写入先渲染为待应用变更卡，用户点击“应用变更”后才写入本地数据库和同步队列；取消不产生任何数据变更。
- 不提供药物计划的 AI 写权限，不提供药物剂量或用药建议。
- 删除卡必须展示对象标题及日程的原时间；任务删除还展示关联日程数量。用户可以逐项取消勾选，再应用余下项目。
- 一个 AI 响应最多包含 10 项变更，工具只接受严格校验的字段；不支持的参数和找不到的 ID 作为卡片错误显示，不写入数据。

## AI 操作协议

客户端向 OpenAI 兼容模型提供一个只生成草案的 `propose_workspace_changes` 工具。工具参数包含 `changes` 数组，单项为：

- `entityType`: `schedule_block` 或 `task`。
- `action`: `create`、`update` 或 `delete`。
- `id`: 更新或删除时必须提供本地 UUID；新建时由客户端生成 UUID。
- `values`: 创建/修改字段。日程使用本地 ISO 时间、类型、锁定状态、重复规则和可选任务 ID；任务使用标题、描述、预计分钟、优先级、状态、截止时间、标签及重复规则。

工具调用只返回已验证的 `AiWorkspaceChangeDraft`，不会持久化。最终 AI 文本必须说明草案已准备好，不能声称已经完成修改。

聊天界面将草案作为该 AI 消息的附属卡片显示。点击“应用已选变更”时，由页面回调依次调用现有日程和任务仓库；所有成功写入使用现有本地操作日志，因此沿用离线同步。部分失败时保留失败项与错误原因，成功项不回滚；用户可重试剩余项。

## 睡眠时段模型与界面

`CheckIn` 保留 `sleepMinutes` 以兼容既有同步记录，并新增可空的 `sleepStartedAt`、`sleepEndedAt`（均以 UTC 存储）。新打卡必须填写两个本地时间：

- 起床时间晚于入睡时间：同一天；否则起床时间视为次日。
- 客户端计算 UTC 起止时间和分钟数，限制时长为 1 分钟至 24 小时。
- 旧打卡没有起止时间时继续显示已有睡眠分钟数；新打卡显示“HH:mm 至 HH:mm，共 X 小时 X 分钟”。

数据库升级新增两列；序列化和同步 payload 同时包含这两个字段，但服务端接受旧客户端缺失字段。

## Markdown 对话显示

引入 `flutter_markdown`，仅将 AI 的消息内容渲染为 Markdown。启用 GitHub 风格的基础文本元素：标题、段落、粗体/斜体、列表、引用、行内代码与代码块；链接必须使用应用主题颜色并由系统外部浏览器打开。用户消息保持纯文本显示，避免用户输入被当作富文本或链接自动执行。解析异常或空内容回退为普通 `Text`。

## 测试与验收

- AI 仓库测试：工具 schema、有效草案、缺失 ID/非法时间/超过 10 项被拒绝。
- 对话页 widget 测试：草案卡展示、取消一项、应用成功、部分失败、Markdown 标题/列表/代码块渲染。
- 领域与数据库测试：跨午夜、同日、边界时长、旧打卡反序列化与新字段 round-trip。
- 运行 `flutter analyze`、完整 `flutter test`、`git diff --check`。

## 非目标

- 不自动应用 AI 变更。
- 不从自然语言推断或修改药物医嘱。
- 不实现任务/日程的多人协作、服务端主动执行或远程控制设备。
