# 日程历史页面设计

## 目标

将已经结束的日程实例从默认日程页面移出，提供独立的历史页面按日期查询，并显示用户实际执行反馈。

## 用户可见行为

- 日程主页 AppBar 右上角显示“历史记录”图标。
- 默认日程主页只显示仍在进行或尚未开始的非重复日程模板，以及包含未来实例的重复日程模板。
- 点击图标进入 `/schedule/history`。历史按结束时间倒序分组为日期。
- 历史页顶部提供日期选择器；默认显示全部历史，选定日期后仅显示本地时区该日结束的实例。
- 每条历史实例展示标题、计划起止时间、类别、`已完成` / `未完成` / `未确认` 状态；未完成时展示用户填写的原因。
- 重复日程模板不因过去实例而从当前页消失；历史页按实际过去的每一次实例生成行，查询窗口默认为最近 90 天，日期筛选可定位任意仍由模板可推导出的日期。

## 数据与边界

历史页不新增持久化实体。它将 `ScheduleBlock` 的过去实例与独立的 `ScheduleFeedback` 按 `scheduleBlockId + occurrenceEnd` 关联；没有反馈的过去实例展示为“未确认”。因此删除/修改日程模板后无法再推导其历史实例；已保存的反馈仍由 AI 与同步功能保留，但历史页不会虚构原模板标题或时间。

日期筛选按设备本地日期计算，存储与同步仍使用 UTC。日期选择不会影响日程、反馈、AI 记忆或同步队列，只改变当前页面的只读查询结果。

## 组件与数据流

1. `ScheduleScreen` 在刷新时以当前时间过滤默认列表，并导航到历史路由。
2. `ScheduleHistoryScreen` 加载账户作用域的日程与反馈，调用 `ScheduleBlock.occurrencesOverlapping` 展开过去实例。
3. 历史条目用实例结束时间匹配 `ScheduleFeedbackRepository.findForOccurrence` 的等价关系；为避免 N+1 查询，页面先读取一次 `scheduleFeedback.list()` 并在内存建立复合键索引。
4. `main.dart` 增加历史路由，保持现有底部导航选中“日程”。

## 错误与空态

- 加载失败显示可读错误与下拉刷新重试。
- 筛选日期无历史时显示“这一天没有已结束日程”。
- 无任何过去实例时显示“还没有日程历史”。
- 无反馈不是错误：明确标记为“未确认”。

## 测试

- Widget 测试验证结束的单次日程不出现在当前页、未来和重复模板仍出现。
- Widget 测试验证历史入口、按日期过滤、日期倒序、未完成原因与未确认状态。
- 领域/页面测试验证跨本地日期的 UTC 实例按本地结束日期归组。

## 安全与回滚

这是纯客户端只读展示改动，无环境变量、密钥、迁移或网络权限变更。回滚只需移除历史路由与入口并恢复当前页筛选；不会删除任何日程或反馈数据。
