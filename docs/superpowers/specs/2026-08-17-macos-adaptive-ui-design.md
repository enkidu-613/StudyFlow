# StudyFlow macOS 自适应桌面界面设计

## 背景

StudyFlow 当前使用一套 Flutter 页面同时服务 Android 和 macOS。移动端底部导航和全宽卡片在 Android 上符合触控使用习惯，但直接铺到 macOS 宽窗口后会出现导航占用方式不自然、内容过度拉伸和留白过大的问题。

## 目标

- Android 保持现有底部导航和触控优先体验。
- macOS 在宽窗口中使用左侧导航栏，更符合桌面应用习惯。
- 业务页面、路由、数据仓库和状态逻辑继续共用，不维护两套页面。
- 页面内容设置合理最大宽度，避免文本和卡片无限横向拉伸。
- 支持窗口缩放，在窄桌面窗口时平滑回退到移动式布局。
- 不改变认证、同步、AI、日程、任务或药物数据行为。

## 方案

在 `StudyFlowShell` 增加基于 `LayoutBuilder` 的响应式壳：

- `maxWidth < 900`：保留当前 `Scaffold + NavigationBar`。
- `maxWidth >= 900`：使用 `Scaffold`，左侧显示固定宽度的 `NavigationRail`/桌面侧栏，右侧显示页面内容。
- 桌面内容区使用 `Center + ConstrainedBox`，默认最大宽度约 1200；AI 对话文本额外限制可读宽度。
- 页面自身只在确实需要时增加 `LayoutBuilder`，优先使用约束而不是检测设备型号。
- 导航项继续使用现有路由列表，保证 Android 与 macOS 的页面入口完全一致。

## 视觉与交互

- 保留现有颜色、图标和中文文案，先解决布局层级，不在本次改动中重做品牌视觉。
- macOS 侧栏显示图标和文字；选中状态使用现有主题色背景。
- 桌面页面保留足够的鼠标/触控板点击区域。
- AI 对话在桌面端避免消息卡片无限变宽，消息内容保持可读行长。
- 不锁定窗口尺寸；由布局约束处理窗口缩放和多窗口场景。

## 文件边界

- `apps/client/lib/features/shell/studyflow_shell.dart`：响应式导航壳。
- `apps/client/lib/widgets/`：如有重复的最大宽度或桌面内容容器，再提取通用组件。
- 需要页面级适配时，只修改对应页面的布局，不改变仓库/API。
- `apps/client/test/`：增加导航壳在窄窗口和宽窗口下的 widget 测试。

## 验收标准

1. Android 仍显示底部导航，现有导航测试和页面测试通过。
2. macOS 宽窗口显示左侧导航，内容不再横向铺满窗口。
3. macOS 窗口缩窄到移动断点以下后回到底部导航，不出现溢出。
4. AI、日程、任务、药物、设置页面均能从桌面侧栏正常打开。
5. `flutter analyze` 和相关 widget tests 通过。
6. 不修改任何用户数据、认证密钥或服务端配置。

## 不在本次范围

- 不迁移到 SwiftUI、React Native 或 Tauri。
- 不重做页面业务交互和数据模型。
- 不添加新的桌面原生能力或菜单栏功能；快捷键作为后续增强项。
