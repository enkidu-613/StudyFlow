# StudyFlow 友好计划与部署模板

将本文件作为输出骨架；按任务删减，不要保留与当前项目无关的占位项。

## 一、先给结论

用一到三句话说明：最终要得到什么、当前阻塞是什么、用户是否需要提供秘密或在控制台操作。

## 二、技术地图

| 层 | 本项目实际采用 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 客户端 | 从仓库确认 | 页面、设备能力、本地安全存储 | 不直接保存服务端密钥 |
| API | 从仓库确认 | 认证、业务数据、同步接口 | 不替代客户端 AI key 管理 |
| 数据库 | 从配置确认 | 用户、任务、日程和同步数据 | 不存明文密码 |
| 反向代理 | 从 `infra/` 确认 | HTTPS、域名转发 | 不负责业务认证 |

若实际技术与计划不同，先列出差异和原因。

## 三、分阶段执行表

每个阶段按下面格式写，不要只给一段命令：

### 阶段 N：<阶段名称>

- **目标**：完成后用户能看到什么。
- **执行位置**：`本机 Mac / VPS / 项目根目录 / server / apps/client`。
- **执行身份**：`普通用户 / sudo / 容器内用户`。
- **前置条件**：文件、权限、域名、备份或密钥。
- **修改文件**：绝对路径或仓库相对路径，以及每个文件的职责。
- **执行命令**：每条命令可复制；复杂命令逐段解释。
- **预期输出**：给出关键成功标志，不伪造完整日志。
- **验证**：命令、页面或接口，以及通过标准。
- **常见失败**：错误症状 → 最可能原因 → 下一条证据命令。
- **回滚**：恢复哪个备份、撤销哪个文件或停止哪个服务。
- **检查点**：明确“通过后才进入阶段 N+1”。

## 四、环境变量说明表

所有 `.env` 变量都使用此表，敏感值只展示变量名或 `<REDACTED>`：

| 变量名 | 作用 | 谁生成/提供 | 在哪里获取或生成 | 应填写什么 | 作用范围 | 敏感？ | 怎么验证 |
|---|---|---|---|---|---|---|---|
| `APP_ENV` | 运行环境 | 部署者 | 根据部署目标决定 | `production` | 服务端 | 否 | 启动日志 |
| `DATABASE_URL` | 数据库连接 | 部署脚本/管理员 | VPS 本地数据库初始化步骤 | 已编码的连接串 | 服务端 | 是 | 数据库健康检查 |
| `JWT_SECRET` | 签发登录令牌 | VPS 自动生成 | `openssl rand -hex 32` | 命令输出 | 仅服务端 | 是 | 登录后受保护接口返回 200 |
| `AI_BASE_URL` | AI 服务地址 | 用户 | 客户端“设置 → AI” | 服务商文档中的兼容 API 地址 | 当前设备 | 通常否 | 设置页连接测试 |
| `AI_API_KEY` | 调用 AI 的凭证 | 用户 | AI 服务商控制台 | `<REDACTED>` | 当前设备 | 是 | AI 测试请求成功 |

实际任务中删除不存在的变量，并为新增变量补齐全部八列。若变量是公开地址，也要说明它不是密钥；若是密钥，要说明不进 Git、日志和截图。

## 五、部署收尾清单
